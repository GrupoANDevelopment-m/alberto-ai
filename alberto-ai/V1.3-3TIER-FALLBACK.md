# Alberto AI v1.3 — 3-Tier Fallback + Multimodal Kimi-K3

## Resposta direta às perguntas

### 1. NemoClaw ainda era stub?
**NÃO mais.** Portei 2 funções REAIS de `upstream/nemoclaw/nemoclaw/src/security/`:
- `safe_resolve_path.ts` → `safe_resolve_path()` Python — bloqueia path traversal (`..`, symlinks) e host-protected zones (`/etc/`, `/var/`, etc)
- `secret-scanner.ts` → `scan_secrets()` Python — 14 padrões de API keys/tokens (NVIDIA, OpenAI, Anthropic, GitHub, AWS, Slack, Discord, npm, Google, Telegram, HuggingFace, Private keys, etc)

**Testado e funcionando** (T3):
- User tentou salvar `nvapi-...` na memória
- NemoClaw BLOQUEOU
- Alberto explicou pro user como fazer certo (env var, secret manager)

### 2. Alberto sabe qual tool/engine usar?
**SIM, agora.** Smart Router v2 (`smart_router_v2.py`) com 10 regras:
- App creation → mimo + alberto_cli
- Code execution → mimo + bash
- URL → hermes + browser
- Web search → mimo + websearch
- Memory → mimo + memory_set
- File write → mimo + write
- File read → mimo + read
- Security → hermes + osv
- Deploy → mimo
- Plan → mimo + plan + engineering squad
- Casual → mimo default

Routing decision é injetada no system prompt pra LLM saber o que fazer.

### 3. Alberto invoca skills por conta própria?
**SIM.** Tool `skill(name, input)` registrada como function_call. Quando LLM decide invocar uma skill, o system chama `run_skill(alberto, name, input)` direto.

### 4. Autonomy testada?
**SIM.** Test T4 executou 3 tasks sequenciais, 2/3 completadas (1 falha por rate limit), arquivos criados fisicamente:
- `/tmp/alberto-task-1.txt` ✓
- `/tmp/alberto-task-2.txt` ✗ (rate limit)
- `/tmp/alberto-task-3.txt` ✓

## 3-Tier Fallback Chain (NOVO nesta versão)

```
User request
    ↓
[1] deepseek-ai/deepseek-v4-pro-0813 (primary)
    ↓ fail (rate limit, 429, timeout)
[2] google/diffusiongemma-26b-a4b-it (fallback)
    ↓ Mavis takes over via Comando: interceptor
    ↓ fail (raro, só se gemma4 também estiver fora)
[3] moonshotai/kimi-k3 (tertiary)
    ↓ multimodal (image + text)
    ↓ reasoning_effort=max, max_tokens=16384
    ↓ Mavis still takes over for tool execution
```

**Verificado**:
- `setup_fallback_chain(alberto)` → tasks=['chat', 'code', 'multimodal', 'reasoning'], fallback_chain=[gemma4, kimi-k3]
- kimi-k3 multimodal test: imagem descrita em português, 84 chunks streamed, 806 tokens total

## Como usar

```bash
# Setup (uma vez)
pip install -e ".[dev]"
alberto model set code nvidia deepseek-ai/deepseek-v4-pro-0813 https://integrate.api.nvidia.com/v1 NVIDIA_API_KEY
alberto model set multimodal nvidia moonshotai/kimi-k3 https://integrate.api.nvidia.com/v1 NVIDIA_API_KEY
alberto fallback   # configura chain de 3 níveis

# Chat normal (usa deepseek-v4-pro)
# "Crie um app FastAPI" → MiMo + write tool + Pydantic Field

# Multimodal (usa kimi-k3 com vision)
# "Descreva esta imagem: https://..."

# Quando deepseek falha (rate limit):
# - Auto-switch para gemma4
# - Alberto emite "MAVIS FALLBACK MODE" + Comando:
# - Mavis (eu) executa

# Skills (Alberto invoca por conta própria via tool):
# "Use a skill app_creator" → skill(name='app_creator')

# Autonomy (tasks sequenciais):
python3 -c "
from alberto import Alberto
a = Alberto()
for task in ['task 1', 'task 2', 'task 3']:
    a.chat(task)
"
```
